## #001 背包打开后无法关闭，需双通道开关（2026-08-19）

### 问题现象

按 B 键打开背包后，再按 B 无法关闭背包，战斗被永久暂停（`pausedForInventory` 一直为 true），只能刷新页面。同时背包缺少鼠标入口，纯点击玩家无法开关背包。

### 根因

`src/states/BattleState.ts` 的 `update()` 中，B 键开关检测写在暂停早退分支**之后**：

```
update(dt, ctx) {
  if (this.pausedForUpgrade || this.pausedForInventory) {
    ...渲染更新...
    return;                    // ← 背包打开时在此提前返回
  }
  ...
  if (ctx.input.isPressed('KeyB')) { ...开关背包... }  // ← 永远执行不到
}
```

背包一旦打开，`pausedForInventory = true`，`update()` 每帧在开头就 `return`，B 键的 toggle 分支成为死代码，形成"只进不出"。

### 修改方案

1. **B 键开关**：将 B 键检测移到 `update()` 最开头（暂停早退**之前**），保证面板打开期间仍能响应关闭；开关逻辑提取为 `toggleInventory()` 统一方法。
2. **背包按钮**：右下角新增常驻 DOM 按钮「行囊 [B]」，点击调用同一个 `toggleInventory()`，实现鼠标开关双通道。按钮 `z-index: 21`（高于面板的 20），面板打开时按钮不被遮挡、仍可点击关闭；点击后 `blur()` 防止按钮持有焦点时空格键（逆刃切换键）误触发 click。
3. **防御处理**：升级三选一面板打开期间不响应背包开关（避免双面板重叠）；`exit()` 时移除按钮、隐藏面板并复位暂停标志，防止状态切换后 DOM 残留。
4. 面板内提示文案由「B 键关闭」更新为「B 键 / 右下角按钮关闭」。

### 涉及文件

| 文件 | 改动 |
| --- | --- |
| `src/states/BattleState.ts` | B 键检测前置；新增 `toggleInventory()` 与 `invToggleBtn` 字段；`enter()` 创建按钮、`exit()` 清理 |
| `src/ui/InventoryPanel.ts` | `injectInventoryStyles()` 追加 `.inv-toggle-btn` 样式；面板提示文案更新 |

### 验证

- Vitest 全量单测通过（269 项，无涉及背包开关的既有用例，无破坏）。
- 运行时冒烟：B 键开 → B 键关 / 按钮开 → 按钮关 / 混合通道（B 开按钮关、按钮开 B 关）均正常；关闭后战斗恢复、穿戴词条即时生效；升级三选一期间 B 键与按钮均不打开背包。

## #002 关卡通关后不回血，残血开新关（2026-08-19）

### 问题现象

通关进入下一关后血量按上一关残血继承：低血量通关时新关从残血开局，刚进战斗房/精英房就濒死，中途只有 4% 概率的休息房（回 30%）可用，暴毙率明显偏高。关卡没有起到"补给节点"的作用。

### 根因

`src/states/BattleState.ts` 的 `onLevelClear()` 只结算通关奖励（经验/碎片/装备）就 `advanceLevel()` + `enterRoom(0)` 进入下一关，全程未处理血量——沿用了"局内血量跨关继承"的隐式行为，与 Rogue 类游戏"关卡=补给节奏点"的通行设计不符。

### 修改方案

在 `onLevelClear()` 结算通关奖励后（胜利判定之前，第 6 关通关同样生效）调用 `this.player.heal(this.player.hpMax)` **回满血**，反馈沿用既有的金光全屏闪 + 升级粒子。经验/装备/背包等局内成长照常继承，仅死亡清空 run。

### 涉及文件

| 文件 | 改动 |
| --- | --- |
| `src/states/BattleState.ts` | `onLevelClear()` 补通关回满血 |
| `wiki/07-level/关卡设计总览.md` | §4 补"通用过渡规则：通关回满血" |

### 验证

- Vitest 全量通过（270 项；`onLevelClear` 依赖 DOM/Canvas 无法单测，走运行时验证）。
- 运行时冒烟：残血通关 → 新关开局满血，HUD 血条立即回满；连续通关两关均生效。

## #003 冲锋怪冲刺无冷却，零前摇无限连冲（2026-08-19）

### 问题现象

恶犬/铁甲护卫/剑奴冲刺结束后几乎立刻再次冲刺，观察不到冷却间隔（恶犬成群时反复贴脸冲撞，无法走位拉扯）。

### 根因

`src/enemy/Enemy.ts` 的 `runBehavior()` 冲刺执行分支中，`dashTimer` 以负值计冲刺剩余、每帧 `+= dt`，跨越 0 时会**过冲为一个很小的正值**（帧时长的余数，如 +0.017s），该剩余值未清零。下一帧进入 `dashTimer > 0` 的蓄力分支，被误判为"新一次蓄力"（该分支不检查 `dashCd`），蓄力瞬间走完 → **零前摇立即再冲**，如此无限循环，冷却完全失效。

次要问题：冷却原从**蓄力触发时**开始计，蓄力（0.4-0.8s）+ 冲刺（0.5-0.7s）本身占用冷却，实际喘息时间比文档口径还短。

### 修改方案

1. **修复零前摇连冲**：冲刺结束帧将 `dashTimer` **精确归零**，杜绝过冲正值被误判为新蓄力。
2. **冷却口径明确化**：冲刺结束时将 `dashCd` **重置为满值**——冷却自冲刺结束起算，蓄力/冲刺本身不占用冷却，冲刺后休息完整冷却时长（恶犬 4s/铁甲 6s/剑奴 5s）才可再次蓄力；蓄力被玩家击打断时冷却仍自当次触发起算（防止打断后立即重新蓄力）。
3. 参数值本身不变（`AIParams.ts` 未改），仅修正计时口径。

### 涉及文件

| 文件 | 改动 |
| --- | --- |
| `src/enemy/Enemy.ts` | 冲刺结束 `dashTimer` 归零 + `dashCd` 重置满值 |
| `tests/simple-enemy.test.ts` | 重写"冲刺后进入冷却"用例（原用例实际依赖 bug 的连冲行为才通过）；新增零前摇连冲回归用例（构造冲刺过冲 +0.05s 时序）与冷却结束再冲刺用例 |
| `wiki/05-enemy/小怪图鉴.md` | §5.1 冲刺参数表补冷却口径说明 |

### 验证

- Vitest 全量通过（270 项）：回归用例在旧代码下必失败（过冲 +0.05s → 下一帧立即再冲），修复后通过；冷却结束再冲刺用例确认恶犬在冲刺结束约 4s 后才会二次蓄力。
- 运行时冒烟：恶犬单冲后有明显追击喘息期，成群时冲撞节奏可读、可走位。

## #004 黑风寨主横扫无攻击范围提示，无法预判躲避（2026-08-19）

### 问题现象

黑风寨主（赵横）横扫为 140px 圆形判定（前摇 0.6s），但前摇期间画面上只有 Boss 本体周身一圈细红光（拼刀窗口提示，半径仅 r+8≈34px），看不出实际攻击范围有多大；玩家贴身缠斗时前摇结束突然掉血，不知道该拉多远才安全，躲避全凭试错。

### 根因

- `src/enemy/Boss.ts` 将横扫/重击的判定半径（140/220）硬编码在 `runAction()` 内部，未对外暴露，渲染层无从得知攻击范围；
- `src/states/BattleState.ts` 的 `drawBoss()` 只绘制了 `clashWindow` 拼刀红圈与破防标记，不存在攻击范围预警的绘制逻辑。

### 修改方案

1. **暴露判定半径**：`Boss` 新增 `attackTelegraphRadius` getter——前摇中的圆形范围技能返回判定半径（横扫 140 / 重击 220），其余动作与直线技能（冲锋）返回 0。判定半径提取为常量 `SWEEP_RADIUS` / `HEAVY_RADIUS`，`runAction()` 伤害判定与预警渲染共用同一数值，杜绝两处口径漂移。
2. **绘制淡淡的预警圈**：`drawBoss()` 在前摇期间以 Boss 为圆心绘制预警圈——橙色极淡填充（α=0.06）+ 半透明虚线描边（α=0.32，`[12,10]` 虚线），与拼刀窗口红光同色系（`#e8763a` 系）；"淡淡的圈"只提示"圈内危险"，不遮挡战斗画面。
3. **通用化受益**：预警圈按动作类型通用生效——欧阳冶重击（220px）、司马烈/天绝老人共用的横扫（140px）同样获得预警；冲锋为直线冲撞，圆圈不适用，维持既有蓄力红光提示（其危险是路径而非圆形范围）。

### 涉及文件

| 文件 | 改动 |
| --- | --- |
| `src/enemy/Boss.ts` | 判定半径常量化（`SWEEP_RADIUS`/`HEAVY_RADIUS`）；新增 `attackTelegraphRadius` getter |
| `src/states/BattleState.ts` | `drawBoss()` 前摇期间绘制攻击范围淡圈（虚线描边 + 极淡填充） |
| `tests/boss-story.test.ts` | 新增预警半径用例：赵横横扫前摇 140 / 前摇结束归 0、欧阳冶重击 220、冲锋直线技能为 0 |
| `wiki/05-enemy/Boss设计.md` | §3.2 补"范围技能前摇显示攻击范围淡圈"通用规则 |

### 验证

- Vitest 全量通过（288 项，含本修新增 3 项预警半径用例；确认前摇结束圈随之消失，冷却期不显示）。
- 运行时冒烟：赵横横扫前摇 0.6s 内 Boss 周围出现 140px 淡橙虚线圈，出圈即安全；欧阳冶重击前摇 1.2s 显示 220px 大圈；圈随出招瞬间消失，不影响后续战斗读屏。

## #005 Boss 的武器（刀体）没有显示出来（2026-08-20）

### 问题现象

进入 Boss 房后 Boss 本体（大圆 + 阶段色 + 蓄力红光 + 破防标记 + 血条）正常渲染，但 Boss 的武器——旋转刀体——一直不出现：既看不到刀柄/刀刃，也看不到青色拖尾。玩家只能凭本体圆与攻击预警圈判断 Boss 位置，无法直观看到"持刀"这一设定，且拼刀/破刀打击点（刀体线段）对玩家完全不可见。

### 根因

`src/states/BattleState.ts` 的渲染层注册 `registerRenderLayers()` 中，刀体统一在 `RenderLayer.Blades` 层由 `BladeRenderer.drawBlade()` 绘制，但该层回调只遍历了**玩家刀体**与**敌人刀体**两类，**漏掉了 Boss 刀体**：

```
this.renderSystem.addLayer(RenderLayer.Blades, (g) => {
  const br = new BladeRenderer();
  for (const b of g2.playerBlades) br.drawBlade(g, b, g2.trailOf(b));
  for (const e of g2.enemies) {
    for (const b of e.blades) br.drawBlade(g, b, g2.trailOf(b));
  }
  // ← 缺少 g2.boss.blades 的遍历
});
```

而 Boss 本体绘制在 `drawBoss()`（属于 `RenderLayer.Enemies` 层）只画圆体与预警/蓄力光，不画刀体——刀体本应由独立的 Blade 层统一绘制。两层职责本身没问题，问题在于 Blade 层的遍历集合不完整：Boss 刀体已在 `enterRoom` 时通过 `engine.addBlade` 注册进碰撞引擎、tick 时也已 `advanceBlade` 推进并 push 拖尾，**仅渲染层遍历遗漏**，导致刀体数据"有碰撞、无画面"。

### 修改方案

1. **补全 Blade 渲染层遍历**：在 `RenderLayer.Blades` 回调末尾追加 Boss 刀体遍历，与玩家/敌人刀体同层、同 `BladeRenderer` 实例绘制（保证品质色/拖尾口径一致）：

   ```
   // Boss 刀体（与玩家/敌人同层渲染，测试小修 #005）
   if (g2.boss) {
     for (const b of g2.boss.blades) br.drawBlade(g, b, g2.trailOf(b));
   }
   ```

   `g2.trailOf(b)` 的 key 为 `${owner}:${ownerId}:${index}`，Boss 刀体 `owner='enemy'`、`ownerId=boss.target.id`，tick 内已 push 过拖尾，渲染链路天然打通，无需额外适配。

2. **不动 `drawBoss()`**：Boss 本体圆与预警/蓄力光仍由 `RenderLayer.Enemies` 层的 `drawBoss()` 绘制；刀体由 `RenderLayer.Blades` 层绘制——维持"本体/刀体分图层"的既有渲染管线分工，避免把刀体绘制塞进 `drawBoss()` 造成图层错乱（刀体会被敌人/玩家本体遮挡）。

3. **回归用例**：渲染层回调依赖 Canvas，单测难直接覆盖遍历逻辑；改以"渲染前提保护"思路在 `boss-story.test.ts` 新增 #005 用例——遍历 6 个 Boss 断言 `blades` 非空且 `active=true`/`owner='enemy'`/`ownerId===target.id`/`length>0`（不被 `BladeRenderer.drawBlade` 的 `if (!blade.active) return` 拦截），并断言 tick 后 `active` 维持 true、刀体中心同步持有者位置。防止未来 Boss.tick 路径或刀体构造改动导致武器再次不可见。

### 涉及文件

| 文件 | 改动 |
| --- | --- |
| `src/states/BattleState.ts` | `RenderLayer.Blades` 回调末尾追加 `g2.boss.blades` 遍历绘制 |
| `tests/boss-story.test.ts` | 新增"Boss 刀体可见性前提（测试小修 #005）"describe 块（2 用例） |
| `wiki/05-enemy/Boss设计.md` | §3.2 补"刀体渲染"通用规则：Blade 层统一绘制需覆盖玩家/敌人/Boss 三类刀体 |
